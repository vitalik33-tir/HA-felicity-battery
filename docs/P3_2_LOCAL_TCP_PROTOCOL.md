# Felicity Wi-Fi Local TCP — протокол и проверенные поля (P3.2)

**Дата:** 2026-11-19. **Проект:** `HA-felicity-battery`.
**Ветка исследования:** `fix/battery-bms-decoding`, основание `04579783c72705fc2a86de4d732967357c15a4af`.
**Область:** чтение батареи **FLA48200-P** через локальный Wi-Fi модуль и описание текущей реализации, а не официальная спецификация протокола.

## 1. Обозначения достоверности

| Метка | Значение |
|---|---|
| **O — наблюдено** | Непосредственно прочитано с установленной FLA48200-P и/или сохранено в обезличенном ответе. |
| **C — сверено** | Интерпретация сопоставлена с другими полями, показаниями HA, конфигурацией, паспортом или независимым измерением. |
| **I — реализация** | Так декодирует наша интеграция; это само по себе не доказывает физическую семантику. |
| **H — гипотеза** | Нет достаточного подтверждения на этой модели/во всех режимах; оставлено для исследования. |
| **E — внешнее** | Описано другими авторами для **их** устройств. Не переносить без собственного сравнения. |

Первичные локальные материалы: `api.py`, `sensor.py`, `binary_sensor.py`, `helpers.py`, `validation.py`, `profiles.py`, `tests/fixtures/fla48200p_standby.json`, результаты P0–P3.1. Серийные номера, IP/имена сети и другие идентификаторы **не** публиковать в примерах.

## 2. Транспорт и порядок чтения — O/I

В данной конфигурации модуль принимает обычное TCP-соединение на **порту 53970**. Клиент передаёт команды ASCII, без CR/LF, затем читает текстовый ответ с JSON-подобными объектами. В текущем клиенте нет TLS, логина и сессионной аутентификации. Это **наблюдение о проверенном обмене**, а не обещание неизменности всех прошивок.

| Этап | Команда, точные ASCII-байты | Ответ | Критичность |
|---|---|---|---|
| 1 | `wifilocalMonitor:get dev real infor` | Текущие значения `Batt`, `Batsoc`, `BatcelList`, `Estate` и др. | **Обязательный** |
| 2 | `wifilocalMonitor:get dev basice infor` | Информация об устройстве/версиях `_basic` | Необязательный |
| 3 | `wifilocalMonitor:get dev set infor` | Настройки и лимиты `_settings`; ответ часто из **нескольких последовательных JSON-объектов** | Необязательный |
| 4 | `wifilocalMonitor:get Date` | Время и Wi-Fi-статус `_date`, в частности `rssi` | Необязательный |

Порядок выполняется **последовательно**, по одному TCP-соединению на команду, **только чтение**. Никаких команд записи, изменения настроек BMS или инвертора клиент не отправляет.

- Период HA `DataUpdateCoordinator`: **30 с**.
- Для явно выбранной **FLA48200-P** `_basic` читается на первом опросе, после сбоя и далее по истечении **300 с**; остальные три команды — каждый цикл. Для других моделей — все четыре каждый цикл.
- До **2 дополнительных попыток** для каждой команды (до 3 обращений), пауза **0,5 с**.
- Таймаут подключения **5 с**, ожидание первого байта **3 с**, межфрагментное ожидание **0,4 с**, полный запрос **15 с**, полный цикл **25 с**.
- Лимит одного ответа **256 КиБ**. Закрытие TCP-сокета ограничено **1 с**.
- При неуспехе обязательного `real` или ошибке модели после повторного чтения весь цикл считается неуспешным; HA не должен объявлять старое измерение новым.
- При отсутствии `basic`, `settings` или `Date` этот источник отсутствует в текущем словаре, но сама телеметрия продолжает работать.

**Ограничение:** нормализация заменяет `None` → `null`, обрабатывает одинарные кавычки и склеенные объекты. Строгая проверка разрыва обнаруживает *незакрытый JSON-объект*; частично испорченный **синтаксически завершённый** JSON не гарантированно отбрасывается универсальным парсером. Для FLA48200-P обязательные поля дополнительно проверяет `validation.py`, для остальных — исходная best-effort логика.

Устройство с портом 53970 следует держать **в доверенной LAN**; не пробрасывать порт в Интернет. В проверенном клиенте нет криптографической защиты обмена.

## 3. FLA48200-P: откуда взята идентификация

- **O:** модель `FLA48200-P` задана явно по шильдику; в ответе `Type=112`, `SubType=7250`, `BMSpara[0][0]=1`, 16 валидных ячеек.
- **C:** производитель указывает **51,2 В / 205 А·ч / 10,5 кВт·ч**; в HA паспортное значение хранится в опции `rated_capacity_ah`, это **не** поле из BMS.
- **O/I:** `Batsoc[0][2]=250000` при делении на 1000 отображается как **BMS Capacity Class 250 А·ч**; не приравнивать к номинальной ёмкости 205 А·ч.
- **E:** другой проект использует `Type=112, SubType=7250` для LUX-E-48250LG03 — следовательно, эти два числа **не доказывают** модель FLA48200-P. Наш профиль включается только с явно выбранным именем модели плюс проверкой структуры полей. Подробнее: [матрица моделей](P3_2_MODEL_EVIDENCE.md).

## 4. Расшифровка основных полей — O/C/I

Числовые примеры ниже взяты из обезличенного ответа 19.11.2026 и подтверждены повторным пассивным опросом. Все массивы индексируются от **нуля**.

| Источник | Пример raw | Формула/выход | Статус, ограничения |
|---|---:|---|---|
| `Batt[0][0]` | `57500` | /1000 → **57,500 В** (`Battery Voltage` округляет до 0,01 В) | O/C, pack DC |
| `Batt[1][0]` | `-1` | /10 → **−0,1 А** | O/I, знак работает в legacy; при малых токах **не** доказывает режим BMS |
| `Batt[2][0]` | `null` | Не использовать как измеренную мощность | O |
| `Batsoc[0][0]` | `10000` | /100 → **100,0% SOC** | O/C |
| `Batsoc[0][1]` | `1000` | /10 → **100,0% SOH** | O/I, прежнее сравнение с интерфейсом; долговременная точность не доказана |
| `Batsoc[0][2]` | `250000` | /1000 → **250,0 А·ч класса BMS** | O/I; **не** паспортная ёмкость |
| `BatcelList[0][0..15]` | `3580..3600` мВ | /1000 → индивидуальные ячейки `Cell 1..16 Voltage` | O/C: 16/16 валидны; экстремумы и сумма близки `Batt` |
| `BatcelList[1][0..15]` | все `65535` | Пустой/резервный ряд, **не** ещё 16 ячеек | O |
| `BMaxMin[0][0..1]` | `[3600,3580]` | /1000 → max/min **3,600/3,580 В** | O/C: сверка с массивом ячеек |
| `BMaxMin[1][0..1]` | `[15,0]` | Нулевые позиции → HA №**16 и 1** | O/C: сверяются с самими ячейками |
| `BMSpara[0][0]` | `1` | **1 физический аккумулятор/модуль** | O/C; число рядов `BatcelList` не равно числу модулей |
| `BTemp[0][0..1]` | `[130,130]` | /10 → **13,0/13,0 °C** | O/I: агрегированные max/min; не два независимо установленных датчика |
| `BTemp[1][0..1]` | `[256,256]` | **Не** трактовать как 25,6 °C двух датчиков | O; семантика не доказана |
| `BtemList[0][0..3]` | `130,130,130,130` | /10 → 13 °C по четырём заполненным ячейкам | O; другие позиции `32767` |
| `LVolCur[0]` | `[576,480]` | /10 → **57,6/48,0 В** | O/I: лимиты заряда/разряда в пакете |
| `LVolCur[1]` | `[0,1500]` | /10 → **0/150 А** | O/I: *runtime* лимиты; 0 не равно аппаратному запрету на заряд без подтверждения |
| `Bfault`, `Bwarn` | `0`, `0` | Raw аппаратные коды BMS | O, ноль в кадре; **битовая расшифровка не верифицирована** |
| `BBfault`, `BBwarn` | `0`, `0` | Другие сырые поля тревог | O, не заменять ими `Bfault`/`Bwarn` |
| `BattList[0][0]` | `57450` | В том же кадре отличается от `Batt=57500` | O; источник/фильтрация канала H |
| `BattList[1][0]` | `-4` | **Не** приравнивать автоматически к `Batt[1][0]=-1` | O; шкала, знак и назначение пока H |

`Battery Power` вычисляется в программном коде, а **не** берётся напрямую из `Batt[2]`: `round((Batt[0][0]/1000) * (Batt[1][0]/10))` Вт. Положительный ток отображается legacy как `charging`, отрицательный как `discharging`; на стоящей в резерве батарее близкий к нулю ток может менять знак из-за квантования. Поэтому `Battery Direction` **не эквивалентен** `Bstate/Estate`.

**Нельзя делать универсальный вывод о масштабе или числе ячеек по числу строк** `BatcelList`. На этой модели массив из **двух** строк, но физические ячейки в `row 0`; `row 1` содержит только `65535`. Для других моделей интерпретация определяется проверкой физических диапазонов, суммарного напряжения и `BMaxMin`.

## 5. Состояния и предупреждения — O/I/H

| Поле/датчик | Что достоверно |
|---|---|
| `Bstate=832 (0x0340)` | **O:** на реальной FLA48200-P при дежурном резервном режиме. |
| `Estate=832 (0x0340)` | **O:** одновременно с `Bstate` в наших кадрах; сейчас `Battery State=Ожидание`. |
| Биты 12/13/14 у `Bstate` | **O:** все равны 0 при 832. Их смысл для этой модели при токовой нагрузке **H**. |
| `Estate` и `Bstate` как разные регистры | **O:** оба сохранены отдельно в скрытом диагностическом датчике; их совпадение при 832 не доказывает общую семантику. |
| `Estate=9152, 5056, 320, 960` | **I/E:** legacy таблица имеет названия charging/discharging/full/standby, но **не подтверждены** на нашей FLA48200-P. |
| `Bfault/Bwarn` | **O:** в проверенных кадрах 0; утверждать расшифровку ненулевых кодов нельзя. |
| `Cell Voltage Drift High` | **I:** мгновенное `drift > 0,030 В`; **не** аппаратный BMS Fault. |
| `Cell Voltage Drift Confirmed` | **I:** 0,030 В в течение 5 мин для включения, ≤0,020 В в течение 5 мин для снятия; программная диагностика, не аппаратный сигнал. |

Особенно важно: отсутствие `Bwarn` в кадре — **не** эквивалент `Bwarn=0`; отсутствие не превращать в «всё нормально». Принудительное обесточивание, смена режимов BMS или изменение инвертора для получения другого `Estate` **не допускаются** в этом этапе. Данные активного заряда/разряда нужны только при естественном событии.

### Разделение уровней проверки

- `validation.py` **до публикации** для FLA48200-P проверяет `Type/SubType`, один модуль, наличие `Batt`, `Batsoc`, 16 ячеек и правдоподобные пределы. Пороги валидатора широкие: pack 15–100 В, ячейки 1–5 В, разница min/max до 100 мВ, сумма ячеек и pack до 2 В. Это защита от повреждённых полей, **не паспортные границы и не пороги безопасности**.
- Исключение валидатора: при ненулевом raw коде аппаратной ошибки `Bfault/Bwarn/BBfault/BBwarn` данные тревоги не блокируются даже при плохих измерениях.
- `profiles.py` **параллельно**, без смены рабочих датчиков, строже проверяет 2–4,5 В/ячейку, sum/pack в пределах 0,8 В, экстремумы ±20 мВ, одноимённую модель. Сравнивает 42 поля с текущим декодером и выдаёт `ready_for_cutover=false`. Это диагностика, а не готовый переключатель.

## 6. Настройки, версии и служебные значения — O/I

| Raw | Пример | HA / интерпретация |
|---|---:|---|
| `_settings.wCVP80` | 3450 | **3,450 В** `Cell Voltage @80%` — настройка, не SOC-измерение |
| `_settings.wCVP20` | 3050 | **3,050 В** `Cell Voltage @20%` |
| `_settings.cVolHi` | 3650 | **3,650 В** `Cell Over Voltage`, предел защиты |
| `_settings.cVolLo` | 2500 | **2,500 В** `Cell Under Voltage` |
| `_settings.bCCHi2` | 2000 | **200,0 А**, порог BMS, не команда на заряд |
| `_settings.bDCHi2` | 2000 | **200,0 А**, порог BMS, не команда на разряд |
| `_basic.version` | "2.10" | Версия Wi-Fi-модуля, **не** BMS |
| `_basic.M1SwVer` | 522 | Исходный основной компонент BCU |
| `_basic.DSwVer` | 65535 | Отсутствует: **BCU = «522 (неполная версия)»** |
| `_basic.M2SwVer`, `CtHwVer` | 6, 0 | **SCU = «6-00-00»** |
| `_basic.DHwVer`, `PwHwVer` | 0, 65535 | **BMU = «Не определена»** |
| `_date.rssi` | −66 | **−66 dBm** от Wi-Fi-модуля |

Служебные значения **зависят от поля**: `65535` обозначает отсутствующее напряжение в пустом `BatcelList[1]` или часть версии; `32767` обозначает незаполненные позиции `BtemList`; `-1` в `Batt[1][0]` — **реальный −0,1 А**, а в других каналах может означать отсутствие. `0` разрешён для токов, флагов и некоторых частей версии. `null` в `Batt[2][0]` не означает нулевую измеренную мощность.

## 7. Безопасные методы проверки и открытые вопросы

Разрешены **только чтение** и обезличенная запись уже разрешённых ответов на локальное хранилище для анализа, без подмены/отправки управляющих команд. Пароль/идентификаторы и все поля `DevSN`, `wifiSN`, IP адреса, токены, MAC и серийные номера должны удаляться из публикуемых файлов. Измерение `BattList` хранить отдельно от `Batt`.

Открытые вопросы: кодирование активных режимов `Bstate/Estate`; знаки/масштабы токов **под реальной нагрузкой**; точная семантика `BTemp[1]`; конфигурационные значения `LVolCur[1]` в нуле; смысл ненулевых аппаратных аварий; поведение на батареях иных моделей/прошивок. Не заполнять пробелы предположениями из сторонней реализации.
