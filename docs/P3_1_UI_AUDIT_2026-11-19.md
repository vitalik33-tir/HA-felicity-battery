## Исправление версий BMS (в экспериментальной ветке)

Реальный ответ get dev basice infor:
- M1SwVer=522, DSwVer=65535;
- M2SwVer=6, CtHwVer=0;
- DHwVer=0, PwHwVer=65535.

До исправления BCU/SCU/BMU показывали 522-655-35, 6-00-00,
0-655-35. Число 65535 — служебное отсутствие второго компонента,
а не настоящая версия 655-35.

Теперь:
- BCU: "522 (неполная версия)" — виден лишь достоверный
  M1SwVer, отсутствующий компонент явно не придумывается.
- SCU: "6-00-00" — формат полностью проверяемого ответа не меняется.
- BMU: "Не определена" — по 0 и 65535 нельзя получить достоверную
  составную версию.
- Все исходные поля (включая 65535) остаются в attributes версии.
- Исходные имена, уникальные ключи и 68 сущностей не менялись.
- Изменена только логика строкового форматирования версий. Устройство
  и TCP-команды не затронуты.

## Неподтверждённое / будущие этапы

- Программные «Cell Voltage Drift High/Confirmed» — не аппаратный
  Fault/Warning от BMS; для интерфейса нужен отдельный согласованный
  подход в P3, не отключая историю и сущности.
- Декодирование активного Bstate/Estate вне 832 всё ещё не подтверждено
  реальным разрядом резервной батареи.
- Нельзя заменить историю и реальный тест одного устройства
  несколькими успешными юнит-тестами.
- Слияние в main — только по явной команде.
