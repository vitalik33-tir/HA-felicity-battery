# Матрица моделей и уровней подтверждения Felicity — P3.2

**Дата:** 2026-11-19. **Назначение:** безопасная маршрутизация модели/формата и список того, что ещё нужно доказать, прежде чем расширять декодер. Эта таблица относится к проекту `HA-felicity-battery`, не к инвертору, отоплению или сторонней системе мониторинга.

## 1. Проверка происхождения данных

Категории: **A — верифицировано на нашей батарее** (реальное чтение + внутренние инварианты); **B — имеется историческая реализация/тесты проекта, но не подтверждено этой батареей**; **C — подтверждение только из внешнего проекта**; **D — неизвестно**.

| Батарея / семейство | `Type/SubType` | Уровень | Что доказано и что запрещено предполагать |
|---|---|---|---|
| **FLA48200-P** (наше устройство) | **112 / 7250** | **A** — только standby | Шильдик и опция модели, 1 модуль, **16 валидных ячеек в `BatcelList[0]`**, второй ряд заполнен 65535, `Bstate=Estate=832`. Сверены raw ток/напряжения, SOC, экстремумы, история HA, паспортные **205 А·ч** и raw класс **250 А·ч**. Семантика активных режимов не проверена. |
| **FLA48200** (без суффикса `-P`) | — | **B/D** | Упоминается в старой README интеграции, но отдельного подтверждённого raw-ответа модели в текущих тестовых фикстурах нет. **Не считать автоматически той же моделью, что FLA48200-P.** |
| **LUX-X-96050HG01** | — | **B** | Legacy-код и комментарии описывают другое устройство с несколькими модулями, где `BatcelList[0]` может содержать модульные напряжения, а индивидуальные ячейки — в `BatcelList[1]`. В P3.2 новое устройство не подключалось; исходный raw-дамп в этой ветке отсутствует. |
| **LUX-E-48250LG03** | **112 / 7250** | **C** | Внешняя таблица другого проекта сопоставляет эти коды с **250-А·ч** батареей. **Коллизия `112/7250` с FLA48200-P**: числовой код не идентифицирует модель однозначно. |
| **FLB48314TG1-H** | 112 / 7353 | **C** | По Matavelli: 314-А·ч батарея, 16 ячеек; класс BMS 350 А·ч. Не тестировалась нами. |

| **LUX-Y-48100HG01 / FLH48100UCG1** | 119 / 201 | **C** | По Matavelli: серия из нескольких модулей, отдельные модульные напряжения. Нельзя автоматически применять профиль 16 ячеек одного модуля. |
| **Любая новая модель** | неизвестно | **D** | Прочитать raw и сверить с паспортом; пока оставить исходный best-effort парсер. Не назначать профиль FLA48200-P только по `Type/SubType`. |

### Почему 112/7250 не означает «FLA48200-P»

Локальная батарея сообщает `Type=112, SubType=7250`, а в сторонней
многомодельной интеграции эти же числа используются для LUX-E-48250LG03.
На нашей FLA48200-P паспорт — 205 А·ч; сам BMS сообщает класс 250 А·ч.
**Гипотеза:** код `SubType` может кодировать класс BMS, а не полный
товарный артикул. Для точной семантики необходимо подтверждение производителя;
не выдавать гипотезу за факт.

Наш экспериментальный профиль проверяет:
`configured_model == "FLA48200-P"` **и одновременно**
`Type=112`, `SubType=7250`, `BMSpara[0][0]=1`, 16 ячеек в
диапазоне 2000–4500 мВ, согласованность с `BMaxMin` и
`Batt`. Если формат не распознан, параллельный профиль не применяется,
рабочие сущности остаются на legacy-коде. Новая модель
**не включается** автоматически в продвинутый декодер.

## 2. Разделение понятий, важных для отображения

| Понятие | Откуда берётся | Состояние для нашей FLA48200-P |
|---|---|---|
| Модель | Шильдик / явно сохранённая опция HA | `FLA48200-P` |
| Паспортная ёмкость | Производитель, HA `rated_capacity_ah` | **205 А·ч** |
| Номинальное напряжение | Паспорт | **51,2 В** |
| Номинальная энергия | Паспорт | **10,5 кВт·ч** |
| Класс ёмкости BMS | `Batsoc[0][2] / 1000` | **250 А·ч** |
| Физическое число модулей | `BMSpara[0][0]` | **1** |
| Число ячеек в серии | Валидные значения `BatcelList[0]` | **16** |
| Напряжение батареи при почти полном SOC | `Batt[0][0] / 1000` | ~**57,5 В** (не равно паспортным 51,2 В; это разные величины) |
| Работа по току | `Batt[1][0] / 10` | Измерения около нуля, знаки меняются, реальный заряд/разряд не исследован |
| Режим BMS | `Estate`, отдельно `Bstate` | **832** в режиме ожидания |

## 3. Не переносить из других устройств без первичных данных

1. **Нельзя** утверждать, что `BatcelList[1]` — индивидуальные ячейки на всех моделях с двумя рядами. У нас там 16 × `65535`, ячейки в `BatcelList[0]`.
2. **Нельзя** трактовать `BattList` как синоним `Batt`. В одном реальном кадре значения отличались на десятки мВ, raw токи отличались по знаку и величине; назначение требует подтверждения.
3. **Нельзя** копировать обработку `-1` из другого проекта: для нашей `Batt[1][0] = -1` — **−0,1 А**.
4. **Нельзя** называть `Bstate=9152` доказанной зарядкой для FLA48200-P. На нашей батарее пока подтверждён только `832`.
5. **Нельзя** показывать BMS raw ёмкость 250 А·ч как паспортную 205 А·ч.
6. **Нельзя** считать `BTemp[1]=256` температурой 25,6 °C; для FLA48200-P физический смысл этого ряда не установлен.
7. **Нельзя** считать программные `Cell Voltage Drift High/Confirmed` аппаратной аварией. Реальные fault/warning — отдельные raw поля.
8. **Нельзя** считать отсутствие поля `Bwarn` кодом 0 или `unavailable` успешным измерением.

## 4. Доказательства для будущего профиля

Перед добавлением ещё одной модели в `profiles.py` собрать **только пассивные разрешённые данные**:

- Точное обозначение с шильдика и номинал (по паспорту/фото; документировать источник, **не публиковать серийный номер**).
- `Type/SubType`, `BMSpara`, `Batt`, `BattList`, `Batsoc`,
  `BatsocList`, `BatcelList`, `BMaxMin`, `BTemp`, `BtemList`,
  `LVolCur`, `Bstate`, `Estate`, `Bfault`, `Bwarn` с **одного** кадра.
- Длительность цикла/моменты опросов, структуру ответов всех четырёх
  **read-only** команд, поведение при потере связи.
- Проверить `sum(ячейки)` против `Batt`, экстремумы, количество
  физически заполненных модулей и честные sentinel значения.
- Если в естественной эксплуатации случатся заряд/разряд/реальная
  аппаратная ошибка: сохранить raw до/во время/после с единым временем
  и одновременно сравнить с устройством или вендорским приложением.
- Новый профиль сначала **shadow**: текущие сущности сохраняются, затем
  сравнение значений, затем тесты, и только после подтверждения реальных
  сценариев — отдельное согласование переключения.
- Отдельно различать «прогнано unit-тестами», «загружено в HA» и
  «подтверждено на оборудовании».

Никаких автоматических операций по отключению сети, переключению
аккумулятора, реле, инвертора или отопления здесь нет и не предусматривается.
